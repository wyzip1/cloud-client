# 1. 有赞开发qa（注意事项）

> 基于有赞 2.0 开发过程中遇到的问题

#### 1. app.json

其中的属性的key必须以`/index`结尾，否则可能会引发问题。<span style="color: inherit; background-color: rgb(251,191,188)">（如</span> <span style="color: inherit; background-color: rgb(251,191,188)">小程序</span> <span style="color: inherit; background-color: rgb(251,191,188)">分享场景）</span>

#### 2. template 模板

* 最外层标签不允许动态展示（如使用 `v-if`、`v-show`）。

* 不支持函数调用，若要处理数据展示，建议用 `computed`，或在给 `data` 赋值前处理。

* 不支持模板字符串，需用字符串拼接。

* 仅 `.js` 文件不支持可选链，相关逻辑请用 `||` 运算符、提前处理初始值，或封装为普通判空。但是`.vue` 文件中可以正常使用可选链式调用（如 `data?.attr`），如果取值判空在能使用链式调用的情况需要优先使用可选链式调用；

#### 3. script 模块

* 若 `watch` 不生效，需使用 `@youzan-cloud/developer-client-presets 1.4.18` 以上版本的依赖。

* <span style="color: inherit; background-color: rgba(255,246,122,0.8)">小程序</span> <span style="color: inherit; background-color: rgba(255,246,122,0.8)">环境自定义组件 </span>`dataReady`<span style="color: inherit; background-color: rgba(255,246,122,0.8)"> 不生效，疑似与文件名称有关，相关问题已反馈，未修复。</span>

* 部分标品页面组件无 `name` 会报错失效，建议所有组件添加 `name`。

* `data/computed`中的数据更新时，若`赋值/返回值`为 `undefined` 不会触发页面更新，如需清空请`赋值/返回值`为 `null`。

#### 4. style 模块

* 样式引入用 `@import "url"`。

* 样式穿透用 `::v-deep`。

* 行内样式style不能换行，标品构建会失败（目前为止2025.12.30）。

#### 5. 多端组件

* 有 pid 属性的多端组件建议全局唯一，否则可能导致组件异常，推荐直接在 data 中生成随机 pid。

#### 6. 开放组件

* 必须放在页面层或插槽层，不能放在自定义组件中。

* 内部不建议使用 tee - ui 组件，大概率导致开放组件失效。



#### 自定义js文件

* 独立 `.js` 文件不能使用可选链式语法；`.vue` 文件中可以正常使用。

* 谨慎导出文件内变量，**<u><span style="color: inherit; background-color: rgb(251,191,188)">此变量在所有import的文件中会被重新声明，一处地方修改，其他引入仍是旧值</span></u>**

```javascript
export const storeState = {};
export function setState(key, value) {
    storeState[key] = value;
}
```

```javascript
import { storeState, setState } from "导出变量";
setState('name', 'lue');
// 输出：{ name: "lue" }
console.log(storeState);
```

```javascript
import { storeState } from "导出变量";

// 等待文件1执行
await runFile1();
// 输出：{}
console.log(storeState);
```

#### 必须特别注意

- 本项目默认 Vue 2 Options API。
- 独立 `.js` 文件不使用可选链；`.vue` 文件中可以正常使用可选链。
- 如果目标项目存在 `styles/global.scss` 且其中已内置 `rpx` 动态单位计算函数，样式单位优先使用 `rpx`；否则使用 `px` 即可。并且使用 `rpx` 时，需要通过相对路径引入 `styles/global.scss`。
- 严格区分全局 `yz.*` API 和页面实例 `this.yz.*` 能力，以文档中的调用对象为准；不要把 `yz.navigateTo` 写成 `this.yz.navigateTo`，也不要把 `this.yz.getPageQuery` 写成 `yz.getPageQuery`。
- 最外层模板节点不做动态展示。
- 开放组件放在页面层或插槽层。
- 所有开放能力以 `zdev-http` 查询的页面/API/插槽/数据文档为准。
- **内容修改完成后仅使用目标项目已有的 ESLint 和 Prettier 做检查或格式化**；没有配置时说明原因，不为检查新增依赖；不需要额外执行 `yarn build` 等构建命令，除非用户明确要求或任务本身必须构建验证。
- 优先使用Tee UI组件库，避免自己造轮子。
- yz数据想要获取最新值不要使用 computed，必须使用 `this.yz.watch` 监听。
    ```javascript
    // 正确示例（全局数据）
    this.yz.watch('user', (user) => {
      console.log(user);
    });
    // 正确示例（页面数据：下单页）
    this.yz.watch('payment', (payment) => {
        console.log(payment);
    });

    // 错误示例 api不能监听对象的某个属性，只能监听对象本身
    this.yz.watch('user.info', (info) => {
        console.log(info);
    });
    ```

# 2. 开放框架与指南整理

## 2.1 开发前必读流程

1. 先确认需求类型：应用定制、页面定制、新增页面、替换页面、开放插槽、开放组件或开放 API。
2. 先阅读本文件，再按需求通过 `zdev-http` 查询对应文档。
3. 涉及开放页面时，必须先读取对应 `页面信息.md`，确认页面 key、平台支持、开放数据、开放 API、开放插槽。
4. 涉及开放 API 时，必须读取对应 API 文档，确认参数、返回值、调用时机、是否支持中断、最低版本。
5. 涉及多端组件、Tee UI、开放组件时，必须读取组件文档，不能直接按 Vue/Vant/浏览器 DOM 经验开发。


## 2.3 仓库结构与开发入口

`cloud` 目录是前端开放 2.0 主要开发目录，建议维持标准结构，不移动固定入口文件。

* `cloud/client`：消费者端定制，使用 Tee 多端框架，支持 H5 与微信小程序。
* `src/app.js`：应用级定制入口，使用 `extendApp`。
* `src/app.json`：应用级配置入口，配置 `cloudPages`、`cloudSlot`、`cloudCustomPages`、微信插件等。
* `src/pages/{pageName}/index.js`：页面级逻辑入口，使用 `extendPage`。
* `src/pages/{pageName}/index.json`：页面级配置，配置模板启用状态和页面开放插槽。
* `src/pages/{pageName}/slot-components/`：页面级开放插槽组件目录。
* `src/slot-components/`：应用级开放插槽组件目录。
* `src/packages/${appName}/...`：新增页面或独立分包目录。

## 2.4 应用配置 app.json

`app.json` 位于 `cloud/client/src`，用于全局配置。

| 配置项 | 作用 | 注意事项 |
| --- | --- | --- |
| `cloudPages` | 定制开放页面 | key 必须使用开放场景页面信息中的页面 key，value 为定制页面入口路径。 |
| `cloudSlot` | 应用开放插槽 | 用于替换有赞应用中全局视图组件，key 必须使用应用开放插槽 key。 |
| `cloudCustomPages` | 新增页面 | key 为新增页面访问路径，value 为新增页面代码路径。 |
| `cloudReplacePages` | 替换页面 | 用于在链接不变时完全替换开放页面，使用前先确认平台和版本支持。 |
| `wxPlugins` | 微信插件配置 | 插件会打入对应应用所属分包。 |

注意事项：

* `cloudPages` 的页面 key 来自开放场景的 `页面信息.md`。
* `cloudCustomPages` 的小程序/H5 新增页面路径通常形如 `packages/${appName}/xxx/index`，其中 `${appName}` 必须使用仓库名称。
* `app.json` 中所有页面属性 key 仍需遵守 `/index` 结尾的项目要求。
* 新增、删除、启用、禁用页面或模板后，如开发者工具不生效，需重跑 `yarn dev` 或 `yarn dev:weapp`。

## 2.5 页面配置 index.json

页面配置文件位于 `src/pages/{pageName}/index.json`，通常是数组结构，支持多模板。

| 配置项 | 作用 | 注意事项 |
| --- | --- | --- |
| `name` | 模板名称 | 必填，同一页面模板名不要重复。 |
| `isEnable` | 是否启用模板 | 必填，只启用需要生效的模板。 |
| `cloudSlot` | 页面开放插槽配置 | 可替换、删除、追加页面插槽，必须使用文档开放的插槽 key。 |

示例：

```json
[
  {
    "name": "页面定制",
    "isEnable": true,
    "cloudSlot": {
      "user-info": "slot-components/user-info.vue"
    }
  }
]
```

## 2.6 extendApp / extendPage / createPage

### extendApp

* 用于扩展全局 App 实例，必须在根目录 `app.js` 中调用。
* 只能调用一次，不需要引入或注册。
* 支持 `onLaunch`、`onShow`、`onHide`、`methods`。
* `onShow`、`onHide` 只支持小程序，H5 不支持。
* 通过 `this.yz.app` 可在页面或组件中访问 App 实例。注意这不是微信 `getApp` 实例。

### extendPage

* 用于扩展开放页面 Page 实例，必须在页面目录 `index.js` 中调用。
* 只能调用一次，不需要引入或注册。
* 支持 `created`、`beforeMount`、`mounted`、`destroyed`、`dataReady`、`methods`。
* `created` 适合注册 hook/event；`beforeMount` 适合发起网络请求；`destroyed` 适合清理事件和定时器；`dataReady` 适合读取 `this.yz.data` 或调用依赖数据的方法。
* `onPullDownRefresh`、`onReachBottom`、`onPageScroll` 等小程序页面事件需注册在 `extendPage` 中，写在 `page.vue` 中不生效。
* `onShow`、`onHide` 只支持小程序，H5 不支持。
* 通过 `this.yz.page` 可在当前页面内访问 Page 实例；应用级定制组件无法访问页面实例。

### createPage

* 用于新增页面或替换页面，必须在新增/替换页面目录的 `index.js` 中调用。
* 只能调用一次，不需要引入或注册。
* 必须提供 `render`，且 `render` 需要返回 Tee 组件。
* `config` 当前主要用于微信小程序页面配置。
* `onShareAppMessage`、`onShareTimeline`、`onPullDownRefresh`、`onReachBottom`、`onPageScroll` 只在小程序有效，需注册在 `createPage` 中，写在 `page.vue` 中不生效。
* 新增页面通常需要 `index.js` 与 `page.vue`。
* H5 新增页面还需要后端路由和 HTML 模板承载，跳转新增页面应使用平台提供的获取路径 API，不手写环境 URL。
* 新增页面内获取参数使用 `this.yz.getPageQuery()`。

## 2.7 开放插槽规则

开放插槽是有赞提前开放的可替换位置，未开放的插槽无法使用。

### 插槽类型

* 页面开放插槽：配置在页面 `index.json` 的 `cloudSlot` 中，只对当前页面生效。
* 应用开放插槽：配置在 `app.json` 的 `cloudSlot` 中，对应用级全局组件生效。

### 插槽配置方式

* 替换默认组件：`"slot-key": "slot-components/slot-key.vue"`。
* 一对多替换：`"slot-key": ["slot-components/a.vue", "slot-components/b.vue"]`，按数组顺序渲染。
* 删除默认组件：`"slot-key": null`，前提是该插槽允许删除。
* 前后插入：每个 slot 默认支持 `before-${slotName}` 和 `after-${slotName}`。
* 配置化定制：部分插槽支持直接传配置对象，避免重写复杂组件。
* Props：循环或上下文场景下，插槽会通过 props 注入上下文数据；具体字段以对应插槽文档为准。

### 动态显隐

* 隐藏前置判断：`this.yz.before[SlotName]Show(callback)`，需要在 `created` 中注册，`slotName` 使用大驼峰。
* 动态显示/隐藏：`this.yz.toggle[SlotName]Show({ isShow: boolean })`。
* 只有通过 `toggle[SlotName]Show` 隐藏的插槽，才能再通过该 API 显示。

## 2.8 开放组件规则

开放组件可以复用开放页面中的默认组件，无需引入，可直接使用。

* client 使用 `<cloud-component cloud-id="id" cloud-class="class" />`。
* 所有开放组件都有 `cloudId` 和 `cloudClass`，用于查询组件实例。
* 通过 `this.yz.queryComponentById(id)` 查询单实例。
* 通过 `this.yz.queryComponentByClass(className)` 查询多实例。
* 开放组件数据只读，不支持直接写；数据写入必须通过开放 Method。
* 依赖开放组件数据或方法时，建议放在组件实例 `dataReady` 回调中执行。
* Method 通常返回 Promise，适合主动调用业务能力。
* Hook 用于拦截默认业务流程，部分 hook 可通过 `Promise.reject()` 中断，也可返回处理后的数据影响后续流程。
* Event 用于监听变更，不支持返回值，不支持中断。
* 开放组件也可能提供 slot，用于定制局部模块。

## 2.9 通信机制

优先使用开放框架提供的通信能力，不使用 `window`、`getApp`、全局变量等非官方通道。

* App 到页面：页面中使用 `yz.event.on` 监听，App 中用 `yz.event.trigger` 触发。
* 页面到 App：通过 `this.yz.app.xxx` 调用 `extendApp` 中的方法或属性。
* 组件到 App：通过 `this.yz.app.xxx` 调用。
* 页面到页面插槽组件：在 `dataReady` 中通过 `this.yz.refs["组件name"]` 获取组件实例。
* 插槽组件到页面：通过 `this.yz.page.xxx` 调用 `extendPage` 中的方法或属性。
* 应用实例到应用级组件：通过 `this.yz.refs["组件name"]` 获取组件实例。
* 组件之间通信：优先使用 props、events、ref；复杂跨层通信再考虑 `yz.event`。
* `this.yz.refs` 获取时机较晚，建议在 `dataReady()` 后使用，过早访问可能是 `undefined`。
* `this.yz.refs` 的 key 与组件 `name` 相关，因此插槽组件必须设置稳定的 `name`。

## 2.10 安全与权限

所有三方代码运行在独立沙箱中，数据、事件、接口、报错互相隔离。

禁止或避免使用以下非多端 API，必须优先使用开放 API 替代：

* 浏览器 API：`top`、`parent`、`window`、`frames`、`location`、`frameElement`、`localStorage`、`sessionStorage`。
* 小程序 API：`wx`、`getApp`、`getCurrentPages`、`Page`、`Components`、`App`。

## 构建与测试
* 小程序构建报错 “没有相关小程序定制代码，无法打包 ... mp-extension/extension.json” 时，可按发布文档创建 `mp-extension/extension.json`。

#### 2. 列表查询

```html
<template>
  <view>
    <t-list
      :loading="loading"
      :finished="isLast"
      finished-text="没有更多了"
      @load="onLoad"
      v-if="list.length"
    >
      <view
        class="custom-item"
        v-for="(item, index) in list"
        :key="index"
      >
      <!-- custom content -->
      </view>
    </t-list>
    <t-empty v-else-if="inited && !list.length" text="暂无数据" />
    <t-toast ref="t-toast" />
    <t-dialog ref="t-dialog" />
  </view>
</template>
```

```javascript
import { Toast as VanToast, Dialog as VanDialog, Empty } from "@youzan-cloud/tee-ui";
import Toast from "@youzan-cloud/tee-ui/dist/toast/toast";
import Dialog from "@youzan-cloud/tee-ui/dist/dialog/dialog";

export default {
  components: {
    "t-empty": Empty,
    "t-toast": VanToast,
    "t-dialog": VanDialog,
  },
  data() {
    return {
      isLast: false,
      loading: false,
      pageNum: 1,
      total: 0,
      list: [],
      inited: false,
    };
  },
  dataReady() {
    this.search(true);
  },
  methods: {
    onLoad() {
      if (!this.inited) return;
      this.search();
    },
    async search(init) {
      try {
        if (init) {
          this.pageNum = 1;
          this.isLast = false;
          this.list = [];
          this.total = 0;
        }
        this.loading = true;
        Toast.loading({
          message: "加载中...",
          forbidClick: true,
          duration: 0,
          context: this,
        });

        const params = {
          pageNum: this.pageNum,
          pageSize: 10,
        };

        const res = await this.yz.app.getApi().requestList(params);

        this.total = res.data.total;
        this.list = [...this.list, ...(res.data.list || [])];
        this.isLast = this.list.length >= this.total;
        this.pageNum++;
      } catch (error) {
        console.log("error", error);

        Dialog.alert({
          title: "错误提示",
          message: (error.data || {}).message || error.message || error.errMsg || "请求失败",
          context: this,
          confirmButtonColor: "#ee0a24",
        });
      } finally {
        Toast.clear();
        this.loading = false;
        this.inited = true;
      }
    },
  },
};
```

评审时优先检查：

- 是否先读取 `docs/前端开发文档.md` 和 通过 `zdev-http` 查询对应文档。
- 是否违反 Vue 2 Options API、多端模板、开放组件、app.json、生命周期、平台版本等约束。
- 是否误把独立 `.js` 文件的可选链限制扩大到 `.vue` 文件。
- 是否按目标项目的 `styles/global.scss` 能力选择样式单位：有内置 `rpx` 动态单位计算函数时优先 `rpx`，否则使用 `px`。
- 是否混淆全局 `yz.*` API 与页面实例 `this.yz.*` 能力；例如 `yz.navigateTo` 不能写成 `this.yz.navigateTo`。
- 页面/插槽/API/数据是否和文档标识、字段、调用时机一致。
- 服务端 API 名称、版本、能力包、token 获取方式、消息 topic、扩展点契约是否和文档一致。
- 是否遗漏 H5/小程序差异、错误处理、loading、空态、重复请求、销毁清理。
- 是否手改生成文件或引入未确认兼容的新依赖。
